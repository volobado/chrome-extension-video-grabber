# 🎬 Video Grabber

**Увидел стоящее видео? Один клик, и оно у тебя на диске.**

Расширение для Chrome: находит видео на той странице, где ты сейчас, и качает его. Без вставки ссылок в мутные сервисы, без «оформите премиум ради 1080p», без очередей ожидания.

## Чем оно лучше остальных

Обычные «качалки видео» бывают двух сортов: расширения, которые умеют только простые MP4 и пасуют перед YouTube, или сайты, где надо вставить ссылку, увернуться от трёх всплывающих окон и получить 480p с водяным знаком. Здесь сделаны обе половины по-человечески:

- **Один клик, никакой возни со ссылками.** Открыл попап, нажал кнопку. Весь процесс. Ролик сохранён раньше, чем ты успел забыть, зачем он был нужен.
- **На YouTube реально забирает максимальное качество.** Современный YouTube отдаёт видео и звук отдельными зашифрованными потоками. Расширения, которые делают вид, что это не так, выдают либо файл без звука, либо 360p. Video Grabber передаёт работу [yt-dlp](https://github.com/yt-dlp/yt-dlp) и ffmpeg: они тянут оба потока и склеивают их. Если на сервере есть 4K со звуком, ты получишь 4K со звуком.
- **Берёт видео, доступные только по логину.** С возрастным ограничением, приватные, по ссылке, по подписке. Расширение отдаёт yt-dlp твои же сессионные куки через собственный API браузера, поэтому ничего закрывать и экспортировать не надо. Подробности ниже: именно на этом спотыкаются все остальные инструменты.
- **Видит то, что страница грузит на самом деле.** Следит за сетевыми запросами и за DOM, поэтому ловит и то, что нигде не показано ссылкой на скачивание, включая HLS-потоки.
- **Загрузку не собьёшь.** Качает не окно расширения, а отдельная служба на твоей машине. Закрыл попап, переключил вкладку, свернул браузер, случайно кликнул мимо: файл всё равно докачается. Открой попап снова, и увидишь тот же прогресс.
- **Плейлист целиком, одной кнопкой.** На странице с плейлистом появляется вторая кнопка. Ролики встают в очередь и складываются в отдельную папку с названием плейлиста, каждый файл с номером по порядку, чтобы ничего не перепуталось.
- **Очередь на виду.** Список загрузок с прогрессом, скоростью и оставшимся временем. Любую можно отменить, упавшую повторить одной кнопкой.
- **Папку выбираешь ты.** Не обязательно «Загрузки»: жми «изменить» и укажи любую, путь запоминается.
- **Всё остаётся у тебя.** Ни аккаунтов, ни серверов, ни телеметрии. Расширение общается только с Python-скриптом на твоей же машине.
- **Не только YouTube.** Движок yt-dlp покрывает около 1800 сайтов. Остальное добирает ловец прямых файлов.

**Приятный бонус:** выбери «Только звук», и получишь MP3. Удобно для лекций, интервью и подкастов, которые проще слушать, чем смотреть.

## Что нужно в системе

| Инструмент | Зачем | Установка |
|------------|-------|-----------|
| **Python 3.8+** | запускает нативный хост | [python.org](https://python.org) |
| **yt-dlp** | качает с YouTube и прочих | `pip install -U yt-dlp` |
| **ffmpeg** | склеивает видео и звук | `winget install Gyan.FFmpeg` |
| **Node.js или Deno** | **обязателен с 2026 года**: YouTube требует JS-движок для расшифровки ссылок на потоки | `winget install OpenJS.NodeJS` |

Установщик проверит все четыре пункта и скажет, чего не хватает.

> Нужны только обычные MP4/WebM? Тогда ничего из этого не нужно, хватит Шага 1.

## Установка

### Шаг 1. Загрузить расширение

1. Скачай или склонируй репозиторий.
2. Открой `chrome://extensions`
3. Включи **Режим разработчика** (справа вверху)
4. **Загрузить распакованное** и выбери папку репозитория
5. Появится иконка 🎬. Закрепи её, чтобы была под рукой.

Прямые файлы качаются уже сейчас. Для YouTube идём дальше.

### Шаг 2. Поставить мост к yt-dlp

Из папки репозитория:

```bash
python install_native_host.py
```

Всё, без аргументов. Скрипт сам найдёт ID расширения, напишет манифест [нативного хоста](https://developer.chrome.com/docs/apps/nativeMessaging/) и зарегистрирует его для Chrome, Edge, Brave и Chromium. Права администратора не нужны.

### Шаг 3. Перезапустить браузер

Полностью закрыть и открыть заново. В попапе внизу должно гореть зелёное **`yt-dlp: готов ✓`**.

## Как пользоваться

Жми иконку 🎬:

**Строка «Сохранять в»**
Показывает папку, куда всё складывается. `изменить` открывает обычный выбор папки, `✎` даёт вписать путь руками, `📂` открывает папку в проводнике. Путь запоминается до следующей смены.

**Верхний блок, «Скачать эту страницу в лучшем качестве»**
Это путь для YouTube и основная кнопка. Нажимаешь красную кнопку, yt-dlp качает видео со страницы, вклеивает звук и кладёт файл в выбранную папку. Выпадающий список задаёт качество: `Макс`, `≤1080p`, `≤720p`, `≤480p` или `Только звук (mp3)`.

Если ты на странице плейлиста, ниже появляется **«Весь плейлист (в свою папку)»**. Расширение читает список, создаёт папку с названием плейлиста и ставит ролики в очередь по порядку: `01 - Название.mp4`, `02 - ...` и так далее.

**Блок «Загрузки»**
Очередь: что качается сейчас, что ждёт, что уже готово. `✕` отменяет, `↻` повторяет упавшую загрузку в ту же папку и с тем же номером. `отменить все` и `убрать завершённые` чистят список.

**Нижний блок, «Найдено на странице»**
Прямые медиафайлы, замеченные на странице. Кнопка `⬇` сохраняет сразу. То, что помечено `HLS`/`DASH`, это потоки, поэтому их кнопка ведёт в yt-dlp.

Цифра на иконке показывает, сколько медиа найдено на вкладке. Если список пуст, нажми ▶ Play на видео и потом ⟳ в попапе: некоторые плееры не запрашивают видео, пока его не запустишь.

**Кнопка 🗗 в шапке** открывает то же окно отдельно от браузера. Попап Chrome закрывается от любого клика мимо, а это окно остаётся на месте: удобно, когда качаешь пачку роликов и хочешь видеть прогресс. Окно следит за активной вкладкой, так что кнопки работают для того, что открыто в браузере прямо сейчас.

## Куки: что нажимать и почему это важно

**Коротко: нажимать ничего не надо, всё происходит само.** Но знать стоит, потому что именно здесь ломаются остальные качалки.

Видео с возрастным ограничением, приватные, по ссылке и по подписке требуют твоего логина. Штатный ответ yt-dlp это ключ `--cookies-from-browser chrome`, который читает базу кук Chrome напрямую. И он отваливается, как только Chrome запущен:

```
ERROR: Could not copy Chrome cookie database
```

Файл заблокирован работающим браузером. То есть «официальный» обходной путь предлагает полностью закрыть Chrome. Что странно, если ты нашёл это видео как раз в Chrome.

Video Grabber обходит проблему с другой стороны. У расширения и так есть законный доступ к кукам через API браузера `chrome.cookies`. Оно читает их оттуда, передаёт локальному хосту, тот пишет временный файл в формате Netscape, отдаёт его yt-dlp и **удаляет сразу после скачивания**. Chrome остаётся открытым, на диске ничего не оседает, за пределы машины ничего не уходит.

Что это значит на практике: **оставайся залогиненным на сайте в том же профиле Chrome**, и закрытые видео будут качаться. Если ролик открывается у тебя в браузере, он скачается и здесь.

> Разрешение `cookies` нужно ровно для этого. Куки уходят в одно место: в локальный процесс yt-dlp на твоём же компьютере.

## Что оно не умеет

Честно, без вранья:

- **Контент с DRM** (Netflix, Disney+, платные платформы) зашифрован по замыслу. Не поддерживается, и обходить эту защиту проект не будет.
- **Blob-видео без исходной ссылки.** Некоторые плееры отдают поток через MediaSource, и скачиваемого адреса просто нет. Кнопка yt-dlp такие случаи всё равно вытягивает, если сайт поддерживается.
- **YouTube регулярно ломает качалки.** Служба сама подтягивает свежий yt-dlp раз в три дня, пока очередь пуста, так что руками обычно ничего делать не надо. Если всё-таки сломалось — обнови вручную: `pip install -U yt-dlp`.

## Если что-то пошло не так

**Внизу пишет `Specified native messaging host not found`**
Мост не установлен или сменился ID расширения. ID выводится из пути к папке, так что перенос папки его меняет. Перезапусти `python install_native_host.py` и перезапусти браузер.

**Загрузка обрывается на середине с `HTTP Error 403: Forbidden`**
Протух yt-dlp: он берёт клиента YouTube, чьи ссылки отдают только начало файла. Обычно лечится само (служба обновляется раз в три дня), вручную — `pip install -U yt-dlp`. В `daemon.log` видно, чем закончилась последняя проверка.

**`Video unavailable`, хотя в браузере ролик играет**
Почти всегда это протухший yt-dlp или отсутствующий JS-движок:
```bash
pip install -U yt-dlp
node --version   # должен что-то вывести
```
Если оба в порядке, ролику скорее всего нужен логин. Проверь, что залогинен на сайте в этом профиле Chrome.

**Доступно только низкое качество, форматов 1080p+ нет**
Не отработал решатель JS-челленджей. Убедись, что `node` или `deno` есть в PATH, и что есть интернет: решатель подтягивается с GitHub при первом запуске.

**Скачанный файл без звука**
Нет ffmpeg, поэтому звуковую дорожку не вклеили. Поставь его и скачай заново.

**Служба загрузок не отвечает**
Логи лежат в `%LOCALAPPDATA%\VideoGrabber\`: `daemon.log` (что делала служба) и `host.log` (как браузер до неё достучался). Там же `settings.json` с выбранной папкой. Служба поднимается сама при первой загрузке и выключается после получаса простоя.

## Как это устроено

```
┌──────────────┐  ссылки на видео  ┌────────────────┐
│  content.js  │ ────────────────► │  background.js │  следит за webRequest и DOM
└──────────────┘                   └───────┬────────┘
                                           │ список медиа, куки
                                           ▼
                                   ┌────────────────┐
                                   │    popup.js    │  интерфейс и очередь
                                   └───────┬────────┘
                                           │ native messaging (stdio + JSON)
                                           ▼
                                ┌─────────────────────┐
                                │ native/yt_dlp_host  │  тонкий клиент, живёт
                                │        .py          │  ровно пока открыт попап
                                └──────────┬──────────┘
                                           │ TCP на 127.0.0.1 + токен
                                           ▼
                                ┌─────────────────────┐
                                │  native/vg_daemon   │  очередь, запуск yt-dlp,
                                │        .py          │  прогресс, выбор папки
                                └─────────────────────┘
```

Ключевая деталь: браузер запускает нативный хост внутри своего job-объекта и убивает всё дерево процессов, как только рвётся связь с попапом. Раньше вместе с хостом умирал и yt-dlp, поэтому загрузка обрывалась на середине с сообщением `Native host has exited`. Теперь качает отдельная служба, которую хост поднимает через WMI: она не наследует job браузера и продолжает работу, что бы ни случилось с окном.

| Файл | Роль |
|------|------|
| `manifest.json` | манифест расширения (MV3) |
| `background.js` | вылавливает медиа из сетевых запросов, собирает файл кук |
| `content.js` | снимает `<video>`/`<source>` со страницы, следит за изменениями в SPA |
| `popup.html` / `.css` / `.js` | интерфейс |
| `native/yt_dlp_host.py` | нативный хост: мост между расширением и службой загрузок |
| `native/vg_daemon.py` | служба загрузок: очередь, yt-dlp, плейлисты, папка сохранения |
| `install_native_host.py` | установщик: сам находит ID расширения и регистрирует хост |
| `_locales/` | переводы интерфейса (английский, русский) |
| `tools/make_screenshot.py` | рендерит скриншот для README из настоящего кода попапа |
| `tools/requeue_failed.py` | возвращает упавшие загрузки в очередь из файла-выгрузки |

Язык интерфейса берётся из языка браузера: русский, если локаль русская, иначе английский.
